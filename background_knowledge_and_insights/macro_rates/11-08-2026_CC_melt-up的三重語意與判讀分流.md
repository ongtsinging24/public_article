## 2. 理論框架

### 2.1 核心定義

**melt-up ＝ 由「怕錯過」而非基本面改善驅動的加速上漲。**

判別特徵不是「漲得快」，而是**上漲本身製造下一輪買盤**的正回饋鏈：

```
價格上行
  → 空頭回補 ＋ 追蹤誤差焦慮的機構補倉
  → call 買盤增加（右尾需求）
  → dealer 為 short call 對沖而買現貨（負 gamma 加速）
  → 價格再上行  ↺
```

與 melt-down 完全對稱：一樣是**強迫性流動（forced flow）**，只是方向朝上。

### 2.2 判讀上最關鍵的一句

> **melt-up 是「機制描述」，不是「方向背書」。**

它同時陳述兩件事：(a) 現在往上；(b) 往上的燃料是**倉位**而非盈餘。
(b) 正是它天然帶 blow-off（末升段）尾巴的原因 —— 倉位燃料會耗盡，盈餘燃料不會。

因此任何把 melt-up 直接翻譯成「加碼」的做法都漏了半句。ROMA 的四個實作全都在處理這半句（§4）。

### 2.3 三重語意（本篇主論點）

同一個字在三個層面指涉不同對象，混用會出錯：

| 層 | melt-up 指的是 | 誤用後果 |
|---|---|---|
| **市場敘事層** | 大盤 regime（SG 週報標題那種） | 拿 regime 當個股進場依據 |
| **個股信號層** | pre-ER call-side 燃料上膛（E1） | 拿個股燃料推論大盤 |
| **評分修正層** | IV 上升的**成因歸因**（crashing-up 非恐慌） | 把「非恐慌」誤讀成「無風險」 |

第三層最隱蔽：`_cap_iv_meltup` 處理的其實是「**IV↑ 這個觀測值該記多空**」的歸因問題，
和前兩層的「行情型態」不是同一件事，只是共用了名字。

### 4.1 方向分流器 —— 高 Skew Rank 的歧義解

`romasys/src/opportunities/sg_signals/skew_regime.py:53`（`classify_skew_regime`）
閾值 `SKEW_RANK_EXTREME = 0.90`（`skew_regime.py:46`；`bias/scoring.py:33` 同值）

根因（檔頭 `skew_regime.py:1-40` 有完整設計契約）：**Skew Rank 是無方向的百分位**，
高 rank 可能來自兩種相反成因 ——

- (a) 極端 **PUT** skew（下行保護需求）→ 真偏空 → `value_trap`
- (b) 極端 **CALL** skew（上行需求）→ 偏多 → **是 melt-up 燃料，不是陷阱**（`skew_regime.py:19`）

判別子 `skew_sign = Call Skew Pct − Put Skew Pct`。互斥三態裁決：

| 條件 | 判定 |
|---|---|
| skew_rank ≤ 0.90 | neutral（兩信號皆不觸發） |
| call-side 主導 | **絕非 value_trap**；再加 Call Wall 上移 + 財報窗 → `bullish_fuel` |
| put-side 主導 且 super_oversold | `value_trap` |
| 其餘 | neutral |

`skew_sign` 缺值 → 退回 legacy（super_oversold + 極端 rank ＝ value_trap）。
接線點：`sg_institutional/layer0.py:92,175`、`sg_institutional/__init__.py:87`。

> 這條直接修正了記憶中「Skew 暴衝壓過 Layer 0 超跌」那條規則的**邊界**：
> 該規則只在 **put-side** 成立；call-side 高 rank 反向。

## 6. 結論與行動

### C1. melt-up 的多空解讀取決於**持倉狀態**，不取決於訊號本身

同一個「RR Rank / Skew Rank 極端 + call-side」讀數：

| 持倉狀態 | 解讀 | 動作 |
|---|---|---|
| 未進場 | **燃料**（E1 gate 可觸發） | 雙層 starter，禁 0 倉觀望 |
| 已持有且接近 52W 高 | **擁擠**（大贏家鎖利情境） | 分批減／保護 |

兩個結論不衝突。這也是 SG 週報自己的做法（§3.1：發現 melt-up → 去找未擁擠側）。

### C2. IV 上升必須先分因，再決定對沖工具

`DR↑ + P/C↓` 同時成立 → IV 上升源自 call 需求，非避險買盤 → **crashing-up**。
此時 vol 變貴，操作含義是：

- 對沖優先 **defined-risk 價差**（如 SG 週報給 DRAM 的 protected bullish risk reversal：
  賣 put spread 融資買 call spread）
- **慎防 long straddle / 裸買 vol** —— 吃 IV crush
- 但**不可**因此把風險分歸零（§4.3 的「只軟化一級」就是這條紀律的程式化）

### C3. 「高 Skew Rank ＝ 偏空」這條啟發式必須帶方向

無方向的 rank 判多空是 V1_P3 原始設計缺陷（`skew_regime.py` 檔頭已載明）。
往後任何用 Skew Rank 的推論，**先問 `skew_sign` 正負**再下結論。

### C4. 引用紀律

melt-up **不是 SG 官方詞條**。要引官方請引具體機制（RR Rank / Synthetic OI / HVP-LVP），
不要引「SG 說這是 melt-up」。

## 7. 待辦（可實證題）

以下皆**尚未驗證**，列為後續實驗題；本篇不做任何 hit-rate 宣稱。

- ☐ **E1 訊號有效度**：`detect_pre_er_bullish_fuel` 觸發後 T+1~T+10 報酬分佈，
  對照組須為「同期同 universe 未觸發、且同樣處於 pre-ER 窗」的標的（**禁用 50% 當基準**）。
  樣本期需含 2025 以前非單邊多頭區段。
- ☐ **確認維度數的邊際價值**：3/2+ 與 5/2+ 是否有可辨別差異，或 `min_confirm_dims=2` 已飽和。
  現況 COHR(5) vs LITE(3) 是天然對照，但 n=2 不可推論。
- ☐ **D7-3「只軟化一級」的校準**：軟化一級 vs 歸零 vs 不軟化，三者對 composite 命中率的影響；
  末升段過熱風險是否真的被這一級留住。
- ☐ **melt-up regime 下 defined-risk vs naked long 的實際損益差**：驗證 C2 的工具選擇建議。
- ☐ **rally_flow == FLOW_SUPPORTED 的獨立辨別力**：它是「事中確認」，需檢查是否只是價格動能的
  同義重述（共線性）而非增量資訊。
