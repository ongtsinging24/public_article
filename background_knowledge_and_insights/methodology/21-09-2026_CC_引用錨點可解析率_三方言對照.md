## CC_ALL_2109_1｜TL;DR

1. **`§` 不是字母，是標點。** Unicode `U+00A7 SECTION SIGN`，category `Po`（Punctuation, other），
   `isalpha() == False`。它專職指「某份文件的第 N 節」，是法條／學術／RFC 的國際通用符號 ——
   **符號本身沒問題，問題在它在我方語料裡的實作方式。**
2. **`§` 自帶「哪一節」，但不自帶「哪一份文件」。** 這是它在跨檔引用場景失效的結構原因，
   不是打字習慣問題。
3. **實測（7,795 個 `.md`）**：`§<章號>` 引用端 **10,634 處**，字面可解析只有 **10.2%**；
   即使放寬到「標題以該章號開頭」也只有 **39.3%**。
4. **對照組（同一把尺，同一份語料）**：ASCII 分層 ID **95.8%**、`[[wikilink]]` **95.6%**。
   ⇒ **差距 ~56pp（寬鬆）／~86pp（字面），不是邊際差異。**
5. **最刺的一條**：8,874 處**裸 `§`**（照定義是「指自己」，理應同檔內必中）
   ——**字面只有 10.5%、寬鬆只有 45.7%**。
   ⇒ **一半以上的自我引用，連在自己這一檔裡都錨不到。**
6. **user「打不出來」與「grep 不到」是同一根尺**：`§` 不在標準美規鍵盤任何一鍵上，
   必須走 Alt code／符號面板／digraph。**打不出來 ⇒ Ctrl+F 搜不到 ⇒ 錨點形同不存在。**
   （同 [[feedback_avoid_adjacent_circled_numerals]] 的 `①②③`，且 `§` 連 EAW=`A` 擠字的毛病都一樣。）

## CC_ALL_2109_2｜理論框架：一個錨點要活下來，要同時過三關

| 關 | 問題 | `§3` | `CC_ALL_2109_3` | `[[卡名]]` |
|---|---|---|---|---|
| G1 可輸入 | user 能不能徒手打出來？ | 🔴 不能（非鍵盤字元） | ✅ 全 ASCII | ✅ 全 ASCII |
| G2 有錨 | 定義端字面上存在嗎？ | 🔴 標題不寫 `§` ⇒ 多半不存在 | ✅ 標題行就是 ID | ✅ 檔名即錨 |
| G3 唯一 | 中的是不是只有它？ | 🔴 `§3` 全庫到處都是 | ✅ FAMILY＋日期＋SYM 隔離 | ✅ 檔名唯一 |

🔴 **關鍵洞見：G1 與 G2 是獨立的失效模式，但長得一樣。**
「打不出來」讓你**無法發動搜尋**；「沒有錨」讓你**發動了也搜不到**。
兩者的外觀都是「Ctrl+F 沒反應」⇒ 只修其中一個（例如改用可打的 `#3`）仍然錨不到。
這是 [[feedback_protection_needs_reverse_control_group]] 的同型：
**防護失效與防護生效在外觀上不可區分時，必須分軸量測。**

**為什麼 `§` 會演化成「只長在引用端」**：寫標題時你在寫**內容**（`## 3. 可證偽觀測點`），
寫引用時你在寫**指路**（`見 §3`）。指路的人自然加符號，寫內容的人不會。
⇒ **這不是誰偷懶，是兩端的寫作動機不同。任何「只有引用端才加」的標記都會長成這樣。**
反過來說，`[[wikilink]]` 之所以 95.6%，是因為**它的錨是檔名 —— 檔名不是誰「加」上去的，是本來就在。**

| 組 | 引用端樣式 | 定義端判準 |

⚠️ **對 B／C 是刻意放寬到全庫、對 A 卻限制在同檔** —— 這個不對稱是**對 A 有利**的：
A 只要求「在自己這一檔裡找到」，是三組裡最低的門檻。

**裸 `§` 的定義**沿用 `.claude/section_id_convention.md:29` 的白名單制：
`§` 前 20 字內出現 `]]`／`前卡`／`.md`／`方法論`／`公約`／`教材`／`SGKNOW`／`README`／`手冊`／`白皮書`
才算「引用別人家」，否則算「指自己」。

### CC_ALL_2109_4_1｜三方言對照（n = 7,795 檔）

| 方言 | 引用端 | 可解析 | **解析率** | 定義端 |
|---|---:|---:|---:|---:|

| A'. `§<章號>`（寬鬆錨） | 10,634 | 4,179 | 🔴 **39.3%** | 537 |
| B. ASCII 分層 ID | 617 | 591 | ✅ **95.8%** | 754 |
| C. `[[wikilink]]` | 25,976 | 24,840 | ✅ **95.6%** | — |

### CC_ALL_2109_4_2｜裸 `§` vs 外部 `§`（A 組再拆）

| 子組 | n | 字面解析 | 寬鬆解析 | 應然 |
|---|---:|---:|---:|---|
| **裸 `§`**（指自己） | 8,874（**83.4%**） | 931（**10.5%**） | 4,053（**45.7%**） | 🔴 理應接近 100%（自己檔內） |
| 外部 `§`（`方法論 §12.5` 等） | 1,760（16.6%） | 152（8.6%） | 654（37.2%） | ⚪ 目標多在庫外，低解析率**可接受** |

🔴 **這一拆才是重點。** 外部 `§` 解析不到是**合理的**（目標根本不在我方語料）。
但**裸 `§` 是自我引用，它的錨就在同一個檔案裡，卻有 54.3% 錨不到。**
⇒ **10.2% 這個總數不是被外部引用拖累的；拖累它的正是自家的那 83.4%。**

### CC_ALL_2109_4_3｜⚠️ 分母 scope 會讓「全庫有幾處 `§`」差到 38%

| 量測方式 | 檔數 | 處數 |
|---|---:|---:|
| `git grep -- "*.md"`（父 repo tracked、只 .md） | 667 | 7,325 |
| `git grep`（父 repo tracked、全檔型） | 817 | 8,053 |
| 檔案系統 walk（含 nested repo ＋ untracked、只 .md） | **979** | **11,909** |

`.claude/section_id_convention.md:120` 記的是「830 檔／9587 處」——
落在上表三個 scope 之間，**無法從數字反推它當時量的是哪一種**。
⇒ 這正是 [[reference_grep_skips_nested_romasys_repo]] 的實例：
**romasys 一家就佔 207 檔**，不顯式帶路徑就整批漏掉。
✅ **操作性後果：任何「全庫有 N 處」的宣稱，必須連量測指令一起寫，否則不可跨日比較。**

### CC_ALL_2109_4_4｜`§` 的字元事實（本機 `unicodedata` 現查）

| 屬性 | 值 | 後果 |
|---|---|---|
| Unicode | `U+00A7` | — |
| 正式名稱 | `SECTION SIGN` | 別名 silcrow／signum sectionis／（德）Paragraphzeichen |

| UTF-8 | `\xc2\xa7`（2 bytes） | — |
| **EAW** | **`A`（Ambiguous）** | 🔴 **與 `①②③` 同病**：終端／編輯器對它算 1 格或 2 格不一致 ⇒ 表格會歪 |
| vim digraph | `Ctrl-K` `S` `E`（本機 `vim -c digraphs` 現查中，值 167） | ✅ 唯一在本機**實測驗證過**的輸入法 |

**輸入方式全表**（除 vim digraph 外，其餘未在本機驗證，屬公開常識）：

| 平台 | 方式 | 對 user 可用？ |
|---|---|---|

| Windows 10/11 | `Win` + `.` 開表情/符號面板 → `Ω` 符號頁 | 🟡 可用但要翻頁，非肌肉記憶 |
| Windows | `charmap.exe` 字元對應表 | 🟡 可用，但等同「複製貼上」 |
| macOS | `Option` + `6` | — |
| Linux／IBus | `Ctrl+Shift+U` → `a7` → `Enter` | — |
| Compose key | `Compose` `s` `o` | — |
| vim | `Ctrl-K` `S` `E` | ✅ 本機已驗 |
| 德語 QWERTZ／北歐鍵盤 | **有專屬鍵**（德語 `Shift`+`3`） | ⚪ **這是它在歐陸法學文獻通行、在美規／中文環境水土不服的原因** |

🔴 **結論：在 user 的鍵盤佈局上，`§` 沒有任何一種「不離開打字流」的輸入方式。**
⇒ 它作為**搜尋錨**的期望價值接近零 —— 不是因為它不好，是因為**發動搜尋的那一步就斷了**。

## CC_ALL_2109_5｜結論與行動

### CC_ALL_2109_5_1｜結論

1. `§` 是**標點不是字母**（`Po`／`isalpha()==False`），語意是「第 N 節」，
   **但不帶「哪一份文件」** ⇒ 跨檔引用天生歧義。
2. 我方語料裡它的實測解析率 **10.2%（字面）／39.3%（寬鬆）**，
   對照 ASCII ID **95.8%**、wikilink **95.6%**。**差距不是風格偏好，是量級差異。**
3. **83.4% 的 `§` 是裸的（指自己），而這批的寬鬆解析率只有 45.7%** ——
   問題出在自家，不在引用外部文件。
4. `.claude/section_id_convention.md` （2026-09-17 定案）定的方向是對的；本篇只是把
   「只長在引用端」從**定性斷言**升級成 **10.2% vs 95.8% 的量化對照**。

### CC_ALL_2109_5_4｜✅ user 裁決（2026-09-21）：`§` 退場，改用 `Sect_` ／ `SSect_`

| 舊 | 新 |
|---|---|
| `§3` | **`Sect_3`** |
| `§12.5` | **`Sect_12_5`**（`.` 仍禁，分層走 `_`） |
| `§§3-5` | **`SSect_3-5`** |

user 原話：「**它是通用型的符號 我理解，但是我要輸入『符號』不容易**」
⇒ **裁決的依據不是 `§` 不好，是 G1（可輸入）這一關過不了**。本篇 CC_ALL_2109_2 的三關框架
正好把這件事講清楚：`§` 在 G2／G3 也有問題，但**G1 才是讓它連搜尋都發動不了的那一關**。

🔴 **配套的硬要求（寫進公約了）：定義端標題也必須帶 `Sect_<章號>`。**

```
定義端：  ## Sect_3. 可證偽觀測點
引用端：  可裁決的事前預測，見 Sect_3
```

**只把引用端的 `§3` 換成 `Sect_3` 是修一半** —— 那只修好 G1，G2 仍然要人工去改標題。
sed 全庫換完會得到「100% 可輸入、仍然 10.2% 可解析」的引用，
**外觀像修好了、實際沒有** ⇒ 這是本篇的量測直接推翻的一條捷徑，已寫進公約〈遷移〉段。

⚠️ **`SSect_3-5` 保留了本公約禁止的連字號範圍**（`grep "Sect_4"` 找不到它）。
這是**刻意保留的取捨**：要引用「3 到 5 這個整體」用 `SSect_3-5`，
要讓每一節都被搜到就**列舉** `Sect_3 / Sect_4 / Sect_5`。不確定時列舉。

⚠️ **`Sect_3` 不是全庫唯一**（每份文件都有第 3 節）⇒ 它是**檔內錨**。
跨檔仍需 `[[卡名]] Sect_3`，已遷移族（AVE／FPT／ST／CC…）自家章節仍用全 ID，不要退回 `Sect_`。
