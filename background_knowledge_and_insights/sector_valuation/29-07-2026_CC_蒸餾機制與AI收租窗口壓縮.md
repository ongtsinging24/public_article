## 1. 理論框架（上）：蒸餾在技術上是什麼

### 1.1 白盒 KD（教科書版，Hinton 2015）

Teacher 對每個 token 輸出整條機率分佈，Student 對齊的是**分佈**而非 one-hot label：

```
Loss = KL( softmax(teacher_logits / T) || softmax(student_logits / T) )
```

- `T`＝溫度；調高會放大「次高選項」的相對權重
- 資訊價值來源稱 **dark knowledge**：「答 A(0.7)、B 也有 0.25、C 幾乎不可能(0.001)」的資訊量，比「答 A」高一到兩個數量級
- **硬前提：拿得到 logits** → 只在**自家模型內部**或**開源權重**可行

### 1.2 黑盒／sequence-level 蒸餾（實務主流，不需 logits）

1. 準備 10^5–10^6 條 prompt（數學／code／agent／多輪對話）
2. 打 teacher 的 API，收回**文字**答案
3. 拿 `(prompt, response)` 直接 SFT

學生學的不是分佈，是**行為**。teacher 的每一條回答已隱含對方花千萬美元級 RLHF 才調出的東西：格式、拒答邊界、解題套路、語氣、工具呼叫寫法。
→ **等於把別人 post-training 的成果買斷，只付 API 費。**

### 1.3 強化變體（真正拉開差距的是這幾條）

| 手法 | 做法 | 為什麼有效 |
|---|---|---|
| Rejection sampling / Best-of-N | teacher 一題生 N 條，用 verifier（數學對答案、code 跑測資）或 reward model 篩最好的才留 | 濾掉 teacher 自身失誤 → 學生資料品質可**高於 teacher 平均水準** |
| **CoT / reasoning trace 蒸餾** | 要完整推理鏈，不只要最終答案 | **2025 年關鍵路徑**。R1 → Qwen/Llama 的公開結果：僅用推理軌跡 SFT，小模型數學表現可越級，**完全不必自己跑 RL** |
| RLAIF / DPO 蒸餾 | teacher 當裁判產 preference pairs，學生跑 DPO | 蒸的是「偏好」而非「答案」，泛化更好 |
| On-policy 蒸餾（GKD） | 學生自己生成，teacher 對學生的輸出打分／糾正 | 避開 exposure bias（學生只見過 teacher 分佈，一旦走偏就不會自救） |
| **自蒸餾／內部蒸餾** | 自家 frontier → 自家小模型，白盒全開 | **Altman 說「我們也蒸餾」指的是這一列** |

### 1.4 ⚠️ 一個修辭層的辨識點（本篇方法論價值之一）

「OpenAI 自己也蒸餾」＝ §1.3 最後一列：**自家打自家，logits／中間層／完整 CoT 全部可用**，用來填滿帕累托前沿的低價端（mini 類產品）。
「別人用你的 API 黑盒蒸餾你」＝ §1.2：**只拿得到文字輸出**。

**兩者技術性質與商業含義完全不同。** 把它們收攏在同一個詞下講，是把對手行為描述成「我們也在做的正常技術手段」，順勢去戲劇化。

> **可移植的判讀紀律**：當一位**利害關係人**用同一個技術名詞同時指稱「自己做的事」與「對手做的事」，先拆開問「白盒還是黑盒／自有還是他有」。這與 [[23-07-2026_CC_hyperscaler_capex_防禦性軍備賽_vs_ROI框架]] §4 的「對人不對框架」是同一類偏誤處理。

### 1.5 成本結構：三個數量級的不對稱

| 階段 | 量級（USD，公開估計） |
|---|---|
| Frontier 預訓練 | 10^8 – 10^9 |
| Frontier post-training（RLHF + reasoning RL） | 10^7 – 10^8 |
| **蒸餾一個逼近它的模型** | **10^5 – 10^6**（API 費 + 千級 GPU-hour） |

**這是全篇的地基**：防禦成本與攻擊成本差三個數量級時，任何「靠防堵維持領先」的策略在數學上都不成立。

## 2. 理論框架（下）：防禦手段與其失效邊界

### 2.1 手段 × 破口

| 防禦 | 擋得住 | 破口 |
|---|---|---|
| 不回傳 logprobs / top-k | 白盒 KD | **完全不擋** §1.2 的 sequence-level 蒸餾，文字本身就夠 |
| **隱藏 CoT**（只給 summary 不給原始推理鏈） | 推理軌跡直接蒸餾 | **最實質的一道牆**；但純 RL（GRPO + 可驗證獎勵）可**自己長出**推理能力。牆擋的是捷徑，不是終點 |
| 帳號封禁 / KYC / 地區封鎖 | 大規模明目張膽的抽取 | 中介 API 商、境外主體、租帳號、二手合成資料集 → 只提高單位成本 |
| ToS 禁止用輸出訓練競品 | 法律風險敏感的公司 | 跨境執行力≈0；且**訓練資料來源極難舉證**（權重看不出資料從哪來） |
| 水印 / canary | 理論上可追溯 | 文字水印極脆弱：改寫／換溫度採樣／混多來源即洗掉；且加水印傷輸出品質 |
| 輸出加噪 / paraphrase | 降低蒸餾效率 | 學生模型會把獨立噪聲**平均掉**；傷付費客戶多於傷蒸餾者 |

### 2.2 根本困境（不是工程問題，是結構問題）

模型一旦透過 API 對外服務，它就是一個**可任意查詢的函數**。query-based model extraction **理論上無法完全阻止**，只能提高查詢成本或降低輸出資訊密度——而這兩件事**同時在傷害正常付費客戶**。

**推論**：「防蒸餾」不能當作護城河的一部分來估值。

### 2.3 三個常被忽略的現實條件

1. **蒸餾來源已不必是 frontier 閉源模型**：open-weight（Qwen / DeepSeek / Kimi / Llama）權重公開且已在 frontier 附近，蒸它們完全合法 → **「封 API」的邊際效益大幅下降**。
2. **污染是雙向且混雜的**：合成資料集普遍多來源混合（互相蒸餾、共用早期公開資料集）→ **「純血統」模型基本不存在**。
3. **⚠️「模型自稱是 ChatGPT」不是蒸餾證據**：網路上海量 LLM 生成文本早已進各家 pretrain corpus → 這是 **identity contamination**。要證明蒸餾需更硬的統計指紋（異常一致的錯誤模式、罕見 token 分佈），**不是自我認知**。這條在判讀「某某模型抄襲」的新聞時是主要的降噪過濾器。

## 4. 結論與行動

### 4.1 核心結論：蒸餾的殺傷力不在「被偷」，在「收租窗口」

一般敘事把蒸餾講成智財問題（誰抄誰）。**這是錯的框架。** 正確的框架是**時間**：

> 蒸餾不改變「誰最強」，它改變的是「最強能收多久錢」。

因為 §1.5 的三數量級成本不對稱 + §2.2 的不可防堵性，frontier 每推出一代，其**行為**在數個月內就會被複製到便宜得多的模型上。領先者永遠領先，但**領先的經濟租金被壓縮到很短的窗口內收完**。

### 4.2 這替 Frame B 補上了技術層因果（本篇對既有框架的主要貢獻）

[[23-07-2026_CC_hyperscaler_capex_防禦性軍備賽_vs_ROI框架]] 的 Frame B 機制是**賽局／心理層**的：「第一個減 capex 的人輸」「CEO 記得的 dotcom 是停止投資的人消失了」。那是**動機**解釋。

本篇提供**技術層的必然性**：

| Frame B 原本的說法 | 本篇補上的技術因果 |
|---|---|
| 「第一個減 capex 的人輸」（賽局直覺） | **因為收租窗口只有數個月**：停止投入下一代 → 現有一代被蒸餾追平 → 定價權在一個產品週期內歸零。不是心理，是**現金流時序** |
| 「capex 與 ROI 脫鉤」（觀察到的現象） | **蒸餾同時做兩件事**：①壓低 frontier 的可實現 ROI（低價端被追平）②提高「必須續投下一代」的必要性 → **脫鉤是機制的必然產物，不是非理性** |
| 「價值流向算力層＋編排層」（Steve Hou） | **模型層可被低成本複製、算力層不能**。蒸餾正是模型層商品化的引擎 → 與該觀察**獨立同向收斂** |

> **關鍵洞見**：Frame A（ROI 論）與 Frame B（軍備賽論）在 07-23 筆記中被當成**互斥**的因果模型。本篇顯示，蒸餾機制讓「**ROI 難兌現**」與「**capex 必須續增**」**同時為真且互為因果**——這正是 Frame B 預測「capex 增、ROI 未證」脫鉤的技術基礎。**ROI 存疑不再是 Frame B 的反證，而是它的組成部分。**

### 4.3 新增差異診斷訊號（併入 07-23 筆記 §3 的可證偽集合）

| 觀測 | Frame A（ROI 論）預測 | Frame B（軍備賽論）＋本篇預測 |
|---|---|---|
| frontier 廠商對 **CoT／API 的開放度** | 無特別方向 | **系統性收緊**（隱藏推理鏈、限流、KYC）＝護城河焦慮的直接證據 |
| open-weight 與 frontier 的**實測差距時間軸** | 無預測 | **持續縮短或穩定在數個月**＝收租窗口壓縮成立 |
| frontier 的**定價路徑** | 隨 ROI 兌現而穩 | **同能力級距價格快速下滑**（被低價端追平所迫） |
| 廠商**自行推出便宜蒸餾版**的節奏 | 依需求 | **主動加速**（先自我蠶食，免得被別人蠶食）＝Altman 帕累托前沿說法的行為對應 |

**若觀測到**：open-weight 與 frontier 的實測差距**持續拉大**（而非縮短/持平），且 frontier 定價在同能力級距上**保持穩定**（無快速下滑）→ **本篇的「收租窗口壓縮」論被證偽**，Frame B 退回純賽局解釋。

### 4.4 行動（可移植紀律）

- **判讀「AI 泡沫」敘事時，區分兩種空頭論證**：
  ①「ROI 沒兌現 → capex 會停 → 相關股崩」＝ Frame A，**本篇機制不支持**（ROI 沒兌現正是續投的原因之一）
  ②「模型層商品化 → frontier 的定價權短暫 → **應用/模型層估值該打折，但算力層不必**」＝ **本篇支持的空頭論證，且它針對的標的完全不同**
  → **不要把兩種空頭論證混為一談**；它們指向相反的持倉調整。
- **不因「capex 停不下來」上修估值倍數**（沿用 [[feedback_conservative_base_pe_no_rerating]]）。本篇只解釋 capex 的**持續性**，**完全不構成**估值 re-rating 依據——續投是被迫的，不是報酬率變好。
- **沿用既有降權邊界**：本篇強化了「AI-capex 高檔不必然是泡沫尾聲」的機制依據，但 [[feedback_ai_capex_momentum_overruns_bearish_structure]] 劃出的失效邊界仍然有效——**2026-07-23 GOOGL 支出側上修導致 capex 反跌 7%** 的案例顯示：受益側可降權偏空訊號，**支出側上修時 capex 是利空**。本篇不推翻該邊界。
- **選模型用實測不用血統**：因 §2.3 的污染混雜，「這模型學自誰」既查不到也不重要。建自己貼實際用途的 eval set，看實測分數。合規敏感場景看的是**授權與 indemnification**（寫在合約裡、可執行），不是訓練資料來源（不可稽核）。
- **新聞降噪過濾器**：見到「某模型自稱是 X ⇒ 抄襲」的報導，直接套 §2.3-③ 判為弱證據。
