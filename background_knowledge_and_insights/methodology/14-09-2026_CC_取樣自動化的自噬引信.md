# 取樣自動化的自噬引信 —— 當「取消硬編碼」把觀察者放進自己的樣本池

> **定位**：本篇是 2026-09-14 14:30–16:10 GMT+8 一場**把整台 WSL 打到 OOM 重啟 4 次**的事故剖析，起因是 `claude-me` session 連續無預警消失。事故本身在 ROMA 測試層，但真正可遷移的是那條**判準**。
> **性質聲明**：這是 **n=1 的事故剖析＋現場量測（forensics），不是實證研究**。沒有對照組、沒有樣本期、沒有 CI，也不應該有——它剖的是一個確定性的程式機制，不是帶雜訊的統計量。唯一具一般性的是第二節的引信形式化與第四節的判準；所有數字只對這次事故、這台機器有效。
> **最大限制**：「含有自己＝必要條件、集合縮到 1＝充分條件」這個劃分**來自單一案例的推理，未在其他 codebase 驗證**。此外修法有效性目前只驗到單檔 `rc=0 / 0.3s / 進程數回 1`；全套 `run_all` 複驗由另一 session 進行中，本篇付印時尚未回報。
> **分工聲明**：根因第二層與修法由並行 session `ongtradingsys-f8` 在 `romasys-wt-pytest4` 樹完成；本篇作者負責止血、log 取證、主樹同構掃描。凡採用對方口徑之處均標明。

## 1. 理論框架 —— 自噬引信的三個構成條件

### 1.1 形式化

設觀察者 `O`（一段會被執行的程式）對一組目標 `S` 逐一施加操作 `f`。自噬遞迴成立需要**三個條件同時滿足**：

| 條件 | 內容 | 本案對應 |
|---|---|---|
| (a) | `S` 由**現況推導**而非硬編碼 | `_samples_by_dialect()` 掃 `tests/test_*.py` 取每方言第一個 |
| (b) | **`O ∈ S`** —— 推導出的集合含觀察者自己 | `test_pytest_bridge_fidelity.py` 自己就是方言 A 的樣本 |
| (c) | `f(O)` 會導致 `O` **被重新執行**（不只是被讀取） | `pytest --collect-only` 會 import 該檔，而該檔的 `@test` 裝飾器**在 import 期就執行檢查** |

缺 (c) 只是浪費一次 I/O；**(a)+(b)+(c) 齊備且 `f` 無深度限制 ⇒ 無界遞迴**。

條件 (c) 是最容易被忽略的放大器。一般直覺是「`--collect-only` 不會跑測試」——這在原生 pytest 成立，但本案的橋接設計把檢查放在 import 期，於是 **collect 等同執行**。

### 1.2 為什麼「取消硬編碼」這個**正確**的重構會反噬

v5.19 那次重構的動機完全正當：硬編碼樣本會**隨遷移靜默失效**（檔案被 Stage 2 搬走後，樣本指向一個不再有代表性的檔，護欄變成永遠綠的空殼）。改成依現況推導確實修掉了這個病。

問題在於它**同時引入了自我指涉**，而兩者不是 trade-off 的兩端：

```
硬編碼樣本        → 靜默失效（護欄假綠）
依現況推導        → 自噬遞迴（fork bomb）
依現況推導 + 排除自身 → 才是正解
```

**「取消硬編碼」與「排除自身」是兩個獨立的正確性要求，修前者不會自動帶來後者。**

### 1.3 必要條件 vs 充分條件（此劃分採 f8 口徑，並修正本文作者初版）

本文作者初版把判準寫成「**集合縮到 1 時會自噬**」。這個寫法**會漏掉引信**：

- **`O ∈ S` 是必要條件**——只要樣本池含自己，池子有 27 個時也只是「抽籤沒抽到自己」。
- **`|S| = 1` 只是充分條件**——它讓抽籤必中。

推論很不舒服但很重要：**v5.19 重構完成的那一天，它就已經是一顆 fork bomb 了**，只是方言 A 當時有 27 檔、檔名序最小者不是它。潛伏了整整一段時間，直到 Stage 2 第三批把方言 A 清空才引爆。

用初版口徑去掃主樹會得到「安全」的誤判——主樹方言 A 有 17 檔，按初版口徑不符合「縮到 1」；按正確口徑則是**帶著上膛的槍**。這個誤判差點讓第四節的 merge 順序約束漏寫。

### 1.4 為什麼 `git log` 找不到兇手

這類地雷有一個共同特徵：

> **引爆的那個 commit 不含引信，含引信的那個 commit 不引爆。**

引爆者（Stage 2 轉檔）碰的是**別的 26 個檔**，`git blame` 到 `test_pytest_bridge_fidelity.py` 只會指向數週前的 v5.19。這使得「程式沒改卻突然炸了」——而事實是**別處的進度推進把最後一個同伴抽走**。

凡是「集合大小會隨專案進度單調變化」的推導式取樣，都該視為帶有時間引信。

## 2. 量測設計 —— 三個互相獨立的資料源

不是實驗，是取證。三源互相獨立，任一源單獨都不足以定案：

| 源 | 取得方式 | 回答什麼 | 單獨用的盲點 |
|---|---|---|---|
| **核心 OOM dump** | `/var/log/syslog` | 誰被殺、何時、殺了幾次、重啟幾次 | **只顯示受害者，不指出兇手** |
| **`/proc` 單次快照** | 自建父子鏈 | 遞迴深度、增速、進程族譜 | 只在事故**進行中**有效 |
| **AST 靜態掃描** | `grep` + `ast.parse` | 引信是否還在、哪些樹帶病 | 看不出是否正在燃燒 |

**⚠️ 兩個假陰性陷阱（此機專屬，已實測）**：

1. `dmesg` 與 `journalctl -k` 在此機（WSL、無 sudo）**都回空**。據此宣告「沒有 OOM」是假陰性——本次差點就這樣誤判。可讀的是 `/var/log/syslog`。
2. `pgrep` 呼叫兩次之間進程會生滅，父子鏈會斷。必須**單次讀 `/proc`** 建樹，否則深度永遠量不出來（實測：`ps -o ppid` 逐層往上走，中途進程就消失了）。

## 4. 結論與行動

### 4.1 判準（可遷移，本篇唯一的一般性產出）

> **看「推導出的目標集合會不會包含發起者自己」，不是「清單是不是硬編碼的」，也不是「集合是不是縮到 1」。**

套用範圍不限測試框架。任何「掃描一組檔案／符號／任務，再對每個施加會觸發自己的操作」都適用：CI 矩陣產生器、lint 的 self-check、文件索引器、code-mod 掃描、以及**任何會 spawn 子 agent 去處理「推導出的清單」的 agent 編排**。

### 4.2 哨兵是深度計數器，不是入口防護（此節採 f8 口徑，且修正本文作者初版理解）

本文作者初版寫成「一個哨兵攔住三個入口」——**錯**。正確機制：

- 三個引爆器 spawn 時**都不帶哨兵**，它們開出來的是**乾淨父程序**，會正常執行檢查（這是設計要的，護欄不能被關掉）。
- 擋住遞迴的是：**那一層自己往下 spawn 時，把哨兵種進子程序**。
- 於是**任何入口進來都只准再往下一層**，深度封在 1。

```
入口(無哨兵) → L1 乾淨執行 → spawn 時種哨兵 → L2 偵測到哨兵 → skip，停
```

**這就是為什麼哨兵必須下在咽喉點而非呼叫點**：`_coupling_probe` 是從 **collect 側**繞進來的，根本不經過案 3 的呼叫端守衛。守唯一 spawn 出口，「新增一個忘了掛哨兵的 case」才炸不起來。

### 4.3 修法三選一的取捨（2026-09-14 定案）

| | 方案 | 裁決 | 理由 |
|---|---|---|---|
| 1 | 哨兵下在 `_collect_ids()` 咽喉點 | ✅ **採用** | 三條 spawn 路徑全收；新增 case 也安全 |
| 2 | 樣本推導排除自身 | ❌ | 只修這一個樣本，補不到其他 spawn 路徑 |
| 3 | `run_all` skip 該檔 | ❌ | 會讓橋接護欄失去偵錯力，而它是卡 ⑧ **唯一防假綠**的東西 |

> **⚠️ 方法論教訓：緊急處置的建議不要直接當修法。** 方案 3 是本文作者止血當下提的，只衡量了「讓它別炸」，沒衡量護欄本身的價值。**止血邏輯與修復邏輯的目標函數不同**，前者求快、後者求不損失能力。

**配套（不可省）**：另加一個 AST 靜態案釘死哨兵那一行存在，並用突變測試驗過會轉紅。否則**哨兵本身就是下一個會被靜默刪掉的硬編碼**——這與 1.2 節是同一個母題。

### 4.4 merge 順序硬條件

> **`ROMA_BRIDGE_SELFTEST` 哨兵與「方言 A 清空」不得分開 merge，且哨兵先行。**

主樹目前帶引信而未引爆（3.4 節）。任何讓方言 A 歸零的 merge 都會讓抽籤必中，主樹就會原樣複製 15:49 那場崩潰——而且很可能發生在 CI 或排程、**沒人盯著**的時候。f8 會寫進 `FEAT_ADD` 卡與 `CHANGE_LOG` v5.20 版塊。

### 4.5 多 session 環境的止血紀律

**砍掉失控進程後必須通知肇事 session**，否則它會立刻重跑同一支。實測：本次砍掉後 **40 秒內**對方就重新啟動，而且第二次連 `timeout` 都沒加。跨 session 的 kill 是**單方面動作**，對方的 context 裡沒有這件事發生過。
