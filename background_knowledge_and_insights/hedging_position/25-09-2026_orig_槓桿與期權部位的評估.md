# 槓桿與期權部位的評估

> 長青知識庫｜適用：含槓桿、ITM call、指數/板塊 ETF 的多頭帳戶
> 通用原理在第一至九節；具體數字集中在第十節的案例（2026-09-25 快照），更新案例時不需改動通用內容。

**縮寫說明**
- SR：Sharpe Ratio，夏普比率
- rf：risk-free rate，無風險利率（程式取 ^IRX，13 週美國國庫券）
- μ / σ：預期（年化）報酬 / 年化波動率
- w：gross 權重（總槓桿倍數）
- SE / CI：standard error 標準誤 / confidence interval 信賴區間
- CAPM：Capital Asset Pricing Model，資本資產定價模型
- ERP：equity risk premium，股票風險溢酬
- β：相對大盤（SPX）的敏感度
- NAV：淨資產；TWR：time-weighted return，時間加權報酬
- C / P：call / put 的權利金；S：標的現價；K：履約價；T：距到期時間（年）；N：合約股數（qty × 100）
- PV(·)：現值；PV(K) = K·e^(−rT)；PV(D)：到期前股利現值
- Δ / γ / θ：Delta / Gamma（Δ 對標的價格的變化率）/ Theta（時間價值衰減）
- IV / RV：隱含波動率 / 實現波動率
- VRP：variance risk premium，波動率風險溢酬（IV 高於日後 RV 的部分）
- ITM / OTM / ATM：價內 / 價外 / 價平；DTE：距到期天數
- LEAPS：Long-term Equity AnticiPation Securities，一年以上長天期期權
- NQ / MNQ：Nasdaq-100 期貨 / 微型 Nasdaq-100 期貨

---

## 〇、核心結論

1. **槓桿不會提高 SR**，只會等比例放大報酬與波動（前提是超額報酬以 w·rf 扣除融資成本）。
2. **用歷史報酬算的「ex-ante」SR 其實是 in-sample 回測**，一年資料的 SE ≈ 1.4，幾乎沒有統計意義。
3. **ITM call ＝ 正股 ＋ 借款 ＋ 內嵌 put**。extrinsic ＝ 利息 ＋ put − 股利。
4. 內嵌 put 對高槓桿帳戶是**槓桿的使用費**（換來沒有強平路徑），不是多餘的保險。
5. 毛保費 ≠ 期望損失：**期望淨成本 ≈ VRP**；毛保費是多頭路徑下的已實現現金流出。
6. 保費的主要來源是**短天期頻繁 roll**；年化保費約 ∝ 1/√T，拉長天期是最直接的優化。

## 一、定義與統計性質

### 1.1 公式

```
SR = (μ − rf) / σ
```

日報酬年化：μ_ann ≈ μ_daily × 252（或 250），σ_ann ≈ σ_daily × √252。

### 1.2 估計誤差

在報酬為 iid 的近似下（Lo, 2002）：

```
SE(SR_ann) ≈ √( (1 + SR²/2) / 年數 )
```

| 資料長度 | SR = 1.0 時的 SE | 95% CI 半寬 |
|---|---|---|
| 1 年 | 1.22 | ±2.4 |
| 3 年 | 0.71 | ±1.4 |
| 10 年 | 0.39 | ±0.8 |

要把 SR ≈ 1 和 0 區分開，大約需要 4 年以上的資料。報酬有自相關或肥尾時，SE 會更大。

**實務規則：SR 必須和 CI 一起呈現，單一數字沒有意義。**

## 二、槓桿與 SR

### 2.1 槓桿在式子裡互相抵銷

以 rf 借入 (w−1) 倍資金，投資未槓桿報酬為 r、波動為 σ₀ 的籃子：

```
槓桿後報酬 = w·r − (w−1)·rf
超額報酬   = w·r − (w−1)·rf − rf = w·(r − rf)
槓桿後波動 = w·σ₀
SR         = w(r − rf) / (w·σ₀) = (r − rf) / σ₀
```

### 2.2 程式實作注意

- 若 ann_ret 已經是「權重 × 標的報酬」（權重總和 = w），分子應扣 **w·rf** 而不是 rf，否則 SR 會被高估。
- log 應同時印出**未槓桿籃子**的 ret 與 vol（= 槓桿值 / w），避免讀者以為槓桿倍數讓 SR 變大。
- 實際融資利率高於 rf 時（例如券商融資 rf + spread），槓桿會**降低** SR。

## 三、SR 的四種口徑

| 口徑 | μ 的來源 | 優點 | 主要偏差 |
|---|---|---|---|
| 歷史回測（現持倉 × 過去 N 天） | 各標的歷史報酬 | 容易計算 | in-sample、動能與倖存偏差；SE 大 |
| θ-adjusted 回測 | 同上，扣期權 carry | 反映期權真實成本 | 扣多少取決於「毛保費 vs VRP」（見第七節） |
| CAPM 先驗 | rf + β × ERP | 不依賴歷史 μ，較保守 | 忽略個別判斷（alpha） |
| 已實現（NAV 序列） | 帳戶實際淨值變化 | 反映真實交易路徑 | 受出入金汙染；需改用 TWR |

### 3.1 為什麼「ex-ante」這個名稱會誤導

用今天的持倉權重套過去一年的報酬，等於假設「過去一年一直持有今天的部位」。今天持有這些標的，往往正是因為它們過去漲過，所以會系統性高估 μ。**歷史平均報酬不是預期報酬**，這是 SR 估計中最大的誤差來源。

### 3.2 CAPM 先驗

```
μ − rf ≈ β_weighted_exposure × ERP        （ERP 常用 4–6%）
SR_capm = (β_weighted_exposure × ERP) / σ_portfolio
```

集中持倉會提高 σ（個別風險），但在 CAPM 下個別風險不被補償，所以 SR_capm 通常很低。**歷史回測 SR 與 CAPM SR 的差距，代表你對「這些標的會持續跑贏」的押注程度。**

### 3.3 Kelly 合理性檢查

```
f* = (μ − rf) / σ²        （未槓桿籃子的 μ、σ）
```

把歷史 μ 代入，若得到遠超實務可行的槓桿（例如 4 倍以上），代表 μ 被高估，不能直接用在部位決策。

### 3.4 已實現 SR

- 出入金會直接汙染 NAV 報酬，應改用 **TWR**（或 Modified Dietz）。
- 需剔除殘缺快照（例如匯出檔被截斷、缺少現金列）。
- 已實現與回測的落差本身有資訊量：反映換倉時機與路徑，而不只是雜訊。

## 四、期權部位的 Δ 線性近似

把期權當作「固定 Δ 的正股」來算報酬，有三個問題：

1. **沒有扣 θ**：拿到了上漲曝險，卻沒有付出取得凸性的成本。
2. **γ 效應**：標的大幅漲跌時，Δ 不可能維持固定，線性近似失真。
3. **σ 被低估或高估**：期權報酬分布不對稱，用線性 σ 描述不完整。

敏感度：每 X pp 的年化 carry 成本，會讓 SR 降低 X / σ_portfolio。

## 五、Put-call parity 與 extrinsic 拆解

### 5.1 推導（歐式、無股利）

| 組合 | 內容 | 到期 S > K | 到期 S ≤ K |
|---|---|---|---|
| A | 1 call ＋ 存 PV(K) 現金 | (S−K) ＋ K ＝ **S** | 0 ＋ K ＝ **K** |
| B | 1 股 ＋ 1 put | S ＋ 0 ＝ **S** | S ＋ (K−S) ＝ **K** |

到期價值恆等，今天價格必須相等，否則有套利空間：

```
C + PV(K) = S + P
C = S − PV(K) + P
```

**買 1 張 call ＝ 買正股 ＋ 借 PV(K) 元 ＋ 買 1 張履約價 K 的 put。**

到期驗證：

| 情境 | 正股 | 還款 | put | 合計 | ＝ call？ |
|---|---|---|---|---|---|
| S > K | S | −K | 0 | S − K | ✓ |
| S ≤ K | S | −K | K − S | 0 | ✓ |

call 的「有限下檔」正是內嵌 put 提供的。對 ITM call 而言，內嵌的是一張 **OTM put**。

### 5.2 有股利時

```
C = S − PV(D) − PV(K) + P

extrinsic = C − (S − K)
          = [K − PV(K)] + P − PV(D)
          =    利息     + put − 股利
```

- **利息 ≈ K·r·T**：沒有真的付出 K 元，等同借款，利息內含在 call 價格中。
- **put**：下檔保護的保費。
- **股利**：call 持有人拿不到，是抵減項。

### 5.3 部位等價與對帳

```
Σ S·N                 ＝ 等效正股名目部位
Σ K·N                 ＝ 隱含借款
Σ S·N − Σ K·N         ＝ intrinsic
Σ Δ_call·S·N − Σ S·N  ＝ 內嵌 put 的 Δ 曝險（為負值）
```

最後一行解釋了為什麼 Δ 曝險會小於名目部位：內嵌 put 已經抵銷了一部分多頭曝險。

### 5.4 限制

- **美式期權**：parity 變成不等式。ITM call 若 extrinsic 小於即將發放的股利，除息前提早履約可能合理，會打破上述拆解。到期前最後一個除息日要留意。
- **r 的選擇**：實際隱含利率可由同到期日 call / put 報價反推，與 ^IRX 會略有差異。
- **IV skew**：put 端 IV 通常較高，put 占 extrinsic 的比例會隨 skew 改變。

## 六、內嵌 put 的功能：槓桿的使用費

### 6.1 常見誤解與修正

| 誤解 | 修正 |
|---|---|
| 融資買正股有「無限下行風險」 | 正股最低跌到 0，損失上限是全部名目部位。問題在於損失**可超過本金**，且中途會被追繳、強平 |
| 內嵌 put 是「不需要的下行保護」 | 只對不加槓桿的帳戶成立。對高槓桿、集中持倉的帳戶，它換來的是**沒有強平路徑** |
| 標的體質好就不需要保險 | 體質影響長期報酬，不會縮小回檔深度（QQQ 2022 約 −35%、2000–02 超過 −80%）。需不需要保險取決於**槓桿與流動性承受度** |

### 6.2 判斷準則

- 未槓桿、可承受大幅回檔 → 內嵌 put 多半是多付的成本，正股較划算。
- 槓桿 > 1.5x、或單一板塊方向性曝險 > 100% NAV → 內嵌 put 是維持槓桿不被強平的必要成本。

體質好讓你敢長期持有，但前提是槓桿部位**活得到長期**。

## 七、保費成本：毛保費 vs 期望淨成本

### 7.1 年化毛保費

```
平均 T      = Σ(K·N·T) / Σ(K·N)          （K 加權）
年化毛保費  = put 價值 / 平均 T
```

### 7.2 兩種成本的意義

| 口徑 | 定義 | 何時成立 |
|---|---|---|
| **毛保費** | put 價值年化 | 多頭持續、put 每期歸零時的**已實現現金流出** |
| **期望淨成本** | 保費 − 期望賠付 ≈ VRP | 長期平均；公平定價時為 0，多付的只有 IV 高於日後 RV 的部分 |

量級參考：IV 比日後 RV 高 2–3 個 vol 點時，VRP 約為保費的一成上下。指數的 VRP 通常比個股明顯。

這是**路徑依賴**的成本：看對方向時付接近毛保費，崩盤時才拿回賠付。

### 7.3 對 SR 的影響

- 估**期望** SR：只扣利息差 ＋ VRP。
- 估**多頭路徑下的已實現拖累**：扣全部毛保費。
- 建議兩者並列，不要只選一個。

## 八、降低 carry 成本的做法

| 做法 | 融資成本 | 內嵌保護 | 強平風險 | 取捨 |
|---|---|---|---|---|
| 短天期 ITM call，頻繁 roll | ≈ rf | 較多 | 無 | 年化保費最高 |
| **拉長天期（LEAPS）** | ≈ rf | 相同 | 無 | 年化保費明顯下降 |
| **更深 ITM（Δ 約 0.85–0.90）** | ≈ rf，借款較多 | 較少 | 無 | put 更 OTM、更便宜；每張占用資金較多 |
| 指數期貨（NQ / MNQ） | ≈ rf | 無 | 有 | 無保費，回到線性部位 |
| 融資買正股 | rf ＋ spread | 無 | 有 | 無保費，利率較高 |
| 降低槓桿 | — | — | — | 最直接，但放棄曝險 |

### 8.1 √T 規則

put 的時間價值約 ∝ √T，所以年化成本約 ∝ 1/√T：

```
新年化成本 / 舊年化成本 ≈ √(T_舊 / T_新)
```

例：平均天期從 0.32 年拉長到 1 年，年化保費約降至 √0.32 ≈ 0.57 倍。此估算對 ATM 附近較準，OTM put 僅供方向參考，需用實際報價驗證。roll 次數減少也會降低交易成本和買賣價差。

### 8.2 roll 時機

DTE 進入 60–90 天後 θ 開始加速。roll 時比較「換下一季」與「直接換一年以上」的**年化 extrinsic**，而不是只比權利金總額。
